# Deployment (PAPER) and known limitations

This build runs **PAPER only**: real Upstox market data, simulated orders. LIVE trading is not available
and must not be enabled. See the [README](../README.md) for setup, the Upstox token flow and the commands.

## Deployment checklist (PAPER)

Once per machine:

- [ ] Python 3.11+ virtual environment created **on this machine**, `pip install -e ".[dev]"` (CPU torch first).
- [ ] `pytest`, `ruff check .` and `mypy .` pass.
- [ ] `.env` created from `.env.example`; `TRADING_MODE=PAPER`; `.env` is not tracked by git.
- [ ] Upstox app created; `UPSTOX_API_KEY` / `UPSTOX_API_SECRET` in `.env`.
- [ ] `DASHBOARD_USERNAME` / `DASHBOARD_PASSWORD` (8+ characters) in `.env`.
- [ ] Telegram bot created; `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` in `.env` (optional but recommended).
- [ ] `python -m config` prints a valid, masked summary.
- [ ] `config/settings.yaml` → `market_session.holidays` contains this year's NSE holidays.
- [ ] Cost rates in `config/settings.yaml` → `costs` checked against the current Upstox / NSE charge sheets.
- [ ] Strategies you want enabled are `enabled: true` in `config/strategy_defaults.yaml`; ML / RL stay off
      (`ml.enabled` / `rl.enabled: false`) until you have models trained on real HISTORICAL data.
- [ ] `learning.loop.enabled: false` until you have a HISTORICAL verification dataset.
- [ ] `python -m data.storage init` (creates / migrates `data/trading.db`).

Every trading day, before 09:15 IST:

- [ ] Fresh Upstox access token in `UPSTOX_ACCESS_TOKEN` (they expire at 03:30 IST).
- [ ] `python -m runtime check --connect` shows no FAIL and the token check passes.
- [ ] `check` lists the strategy version you expect for each strategy (YAML or a learned PAPER deployment).
- [ ] No persistent kill switch left from yesterday, or it was reviewed and reset by a named operator.
- [ ] Start: `python -m runtime paper` (or `docker compose up -d`), then the dashboard.
- [ ] Dashboard shows **PAPER**, a live heartbeat, the WebSocket connected, today's instrument list loaded,
      and the expected autonomy level.
- [ ] Telegram: alerts arriving (the first entry, or any WARNING / CRITICAL alert).

After the close:

- [ ] After 15:20, every PAPER position is closed (dashboard / end-of-day summary "Open trades after the
      close: 0").
- [ ] End-of-day summary received; review rejected orders, kill-switch events and errors in `logs/bot.jsonl`.
- [ ] Stop the session (Ctrl+C / `docker compose stop bot`), or use `--stop-at 15:40`.
- [ ] If the learning loop ran: read the report in `reports/learning/`; a deployed version runs from the
      next start (`python -m runtime check` shows it). Roll back from the learning tab if needed.

## Known limitations

**By design in this build**

1. **No LIVE trading.** There is no LIVE order routing. `TRADING_MODE=LIVE` is refused at config load,
   `UpstoxRestClient` order methods always refuse, the broker factory only builds `PaperBroker`, the
   database cannot record a LIVE deployment, and the dashboard's LIVE request is always refused.
2. **No real historical data.** Every ML / RL model and every learning-loop run so far used SYNTHETIC data,
   and nothing can be promoted from it. The PAPER session's own journal (labelled `LIVE_FEED`) is real
   evidence for LIVE_CANDIDATE nominations only; VERIFY still needs a HISTORICAL dataset.
3. **"HISTORICAL" is an operator attestation.** A dataset counts as real because its `meta.json` says so
   (SYNTH-tagged instruments are refused). Label only data you recorded from the market.
4. **Learned deployments apply at start-up only.** A version the loop deploys during a session runs from the
   next start; a running session never changes its strategy config.
5. **Dashboard autonomy changes are capped by YAML across restarts.** A switch to a more restrictive level
   survives a restart; raising the level above `app.autonomy_level` lasts only for the running session.

**Operational**

6. **Daily manual token.** The Upstox access token must be generated by hand each day. An expired token
   trips the kill switch (`AUTH_FAILURE`, persistent) at the next Upstox call; restart with a new token and
   reset the kill switch as a named operator.
7. **Positions are protected only while the bot runs.** PAPER positions left open across a shutdown are
   restored at the next start, but nothing monitors their stops in between.
8. **PAPER fills are a model.** Fills use the top-of-book quote plus `slippage_ticks`, with partial fills
   capped at the quoted size. Queue position, latency, exchange-side SL-M behaviour and freak trades are not
   modelled; real fills will differ. Charges follow the configured rates.
9. **Single process, single machine.** One SQLite database (WAL), one market-data WebSocket, Upstox normal-
   plan subscription limits. The learning loop runs after the close in a worker thread of the bot process;
   while it runs, the heartbeat can be slower.
10. **Holiday calendar is manual.** Add each year's NSE holidays; without them every entry is blocked.
11. **Telegram is outbound only** (no commands). A failure that logs CRITICAL and also raises its own
    CRITICAL alert (e.g. an exit failure) can produce two messages.
12. **Docker was not built on the development machine for this release** (Docker is not installed there).
    The Dockerfile and compose file are syntax-checked only; build and run `docker compose run --rm bot
    python -m runtime check` before relying on them.

**Carried audit warnings** (see `docs/audits/phase-10-risk-execution-audit.md` for the full list)

13. An RL management decision is persisted after it is applied; if that write fails, one applied action per
    strategy per session has no audit row (RL is then suspended for the strategy).
14. Risk events outside a trade's window (creation → exit + 30 min) are not attached to its journal row.
15. While RL is suspended, its HOLD decisions keep trying to write and log every minute.
16. ML / RL inference runs synchronously on the event loop.
