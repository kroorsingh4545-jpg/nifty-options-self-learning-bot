## Warnings

1. **RESOLVED (2026-11-05).** See area 17. What remains: backtests (`python -m backtest --data`) still read a missing `meta.json` as HISTORICAL, which affects only the report label. Data that is synthetic but carries no `SYNTH` tag (for example, real-looking instrument keys written by another tool, or deliberately rewritten keys) can't be detected from the data itself, so the explicit `source` stays an operator attestation. Original finding: **A dataset without `meta.json` is treated as HISTORICAL.** `load_dataset` defaults `source` to `"HISTORICAL"` (`backtest/data.py:159`), and `python -m ml train --data` routes by that label (`ml/__main__.py:73`). A SYNTHETIC dataset saved with `save_dataset` and then stripped of `meta.json` (or written by another tool) would train into the **trading** registry as HISTORICAL. Every DB/registry guard would then treat it as real data. It still needs every gate to pass, a named human `mark_paper_ready`, `ml.enabled: true` and `ml_models` passed to the bot. Even then it could only veto or shrink entries. But this is the one path around the "never register a synthetic-trained model as production" rule. Recommended fix: the ML layer should refuse datasets with no explicit `meta.json` source, and refuse any dataset whose instrument keys or symbols carry the `SYNTH` tag (`backtest/synthetic_data.py:39`) unless it is labelled SYNTHETIC.
2. **Inference runs synchronously on the event loop, inside the engine's entry lock.** Each ML-enabled signal does LightGBM prediction (5 seeds × up to 1 + 4 + 2 heads), an implied-volatility bisection, a query of **all** of the strategy's closed trades (`runtime/ml.py:57`, unbounded over time), and a snapshot insert. Signals are rare, so this should be milliseconds, but while it runs, ticks wait, and those ticks drive the local stop monitoring of open positions. Bound the outcomes query (last N trades) and measure the latency before enabling ML in PAPER.
3. **Training/serving skew on quote fields.** Training data are candles: `option_spread_pct` is always NaN, and IV is always solved from the premium. Live, spread and feed IV are present (`runtime/ml.py:52-53`). LightGBM can't split on an all-NaN training column, so spread has no effect today. A model trained on recorded live snapshots and served on candle-only data (or the reverse) would see a different distribution. Document the source of each field in the manifest, and train only on the same kind of data the model is served on.
4. **DELAY is a veto, not a re-queue.** A DELAY decision (`ml/signal_filter.py`) refuses the signal now. Whether it is "re-evaluated" depends on the strategy emitting it again (ORB counts only approved entries). The behaviour is documented (`docs/ml-layer.md`), but the name suggests more than the code does.
5. **Promotion has no autonomy-level check.** `ModelRegistry.mark_paper_ready` accepts any non-empty `approved_by` string and doesn't consult `app.autonomy_level`. That's acceptable for Phase 7 (no HISTORICAL model exists, and LIVE is unreachable from `ml/`, `ml/model_registry.py:270`), but the Phase 9 promotion gate must own this transition.
6. **A failed snapshot write doesn't block the decision** (`ml/inference_service.py:196-203`). The decision still goes to the risk gate and the trade row still records `ml_confidence` / `regime`, but the full feature vector for that decision would be missing from the audit trail.
7. **Event-level trading metrics are optimistic about concurrency.** `ml/evaluation.py` sizes each event independently and ignores max open trades, daily caps, cooldowns and the kill switch (stated in the module and in every report). The full backtest with `BacktestOptions(ml_strategies=..., ml_models=...)` covers this, and should be the Phase 9 VERIFY step.
8. **Carried over from Phases 5–6** (unchanged by this phase): `settle_simulation` relies on CPython `loop._ready`; a failed square-off is carried overnight in the paper broker; backtest logs carry wall-clock times; funds are read every second; one shared dashboard account; reset with open positions; `--allow-remote` TLS; the instrument list is parsed on the event loop; there is no production PAPER runner (so `load_strategy_models` has no production caller yet).
